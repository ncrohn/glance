# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Glance is a macOS markdown viewer/editor built with **Tauri 2** (Rust backend + vanilla TypeScript frontend, no UI framework). The CLI entry point is `mdview <path>`, which opens files as tabs in a single reused window.

## Commands

```bash
pnpm install                 # install JS deps (pnpm only — see packageManager pin)
pnpm tauri dev               # run app with hot reload
pnpm test                    # frontend unit tests (vitest)
pnpm test:watch              # vitest watch mode
pnpm exec vitest run src/store.test.ts   # single test file
pnpm exec tsc --noEmit       # TypeScript type check
pnpm build                   # production JS build (tsc + vite)
cd src-tauri && cargo test   # Rust unit tests (CLI path resolution, anchor, annotations, setup)
cd src-tauri && cargo test --bin glance-mcp   # MCP server unit tests (view/resolve logic)
bash scripts/install.sh      # release build → copy Glance.app to /Applications + install mdview wrapper
```

## Architecture

Two halves talk only over Tauri's IPC (`invoke` for commands, `emit`/`listen` for events). The TS wrapper for every IPC call lives in `src/ipc.ts` — add new commands/events there, never call `invoke`/`listen` from elsewhere.

### Frontend (`src/`)

Pure-reducer pattern. `app.ts` holds a single `State` and fully re-renders the DOM on every change (`render()` → `renderTabBar`/`renderActions`/`renderContent`). The logic modules are pure and unit-tested in isolation; `app.ts` is the only side-effectful glue:

- `store.ts` — `State` reducers (`openDoc`, `closeDoc`, `toggleViewMode`, `applyDiskChange`, `markSaved`, …). Each returns a new state; never mutate. A `Doc`'s `id` is its `absPath`, so opening a duplicate path dedupes/focuses.
- `document.ts` — `Doc` shape; `isDirty` = `editorContent !== diskContent`.
- `reload.ts` — clean tab → `auto-reload`, dirty tab → `prompt`.
- `tab-menu.ts` — the tab right-click menu: `tabMenuEntries` (items + enabled state), `tabsToClose` (Close / Close Others / Close to the Left / Close to the Right), and `parentDir`. `app.ts` pops it as a native menu via `popupContextMenu` and runs the pick in `runTabMenuAction`; bulk closes go one tab at a time through `closeTab` and stop at the first Cancel on an unsaved prompt.
- `session.ts` — open-paths / recent-files lists (persisted to `localStorage`).
- `renderer.ts` — markdown-it + highlight.js (`html: false`).
- `editor.ts` — CodeMirror 6 editors; themes read CSS custom properties so they track the active theme. `mountEditor` is the whole-file source view (⌘E); `mountBlockEditor` is the in-place editor for click-to-edit, which inherits the clicked element's typography and dims markdown marks. The `dark` flag is passed in by `app.ts` from the active theme's appearance (CodeMirror's own default only).
- `block-edit.ts` — pure line-range helpers for click-to-edit: slice/splice a unit's source lines into the doc, place the caret from the clicked rendered text, trim a list item's trailing blank line, find a code fence's body.
- `find.ts` / `find-bar.ts` — find in file. Edit → Find… (⌘F), Find Next (⌘G) and Find Previous (⇧⌘G) emit `menu-find`. The bar lives on `#workspace` so renders don't remove it, and `render()` re-runs the search. The formatted view is painted with the CSS Custom Highlight API (no DOM changes); the ⌘E source view uses a CodeMirror decoration field (`showFind` on the editor handle).
- Updates — `checkForUpdates` in `app.ts` asks the updater plugin (`checkForAppUpdate` in `ipc.ts`) for the signed `latest.json` on the latest GitHub release. The daily launch check downloads quietly, then offers "Restart to update". Glance → Check for Updates… offers Update and Restart. Both settle unsaved tabs first, the same way quitting does. A blocking progress modal (`showUpdateProgress`) then stays up through download, install and restart, and unsaved tabs are checked once more before the restart, since `relaunch` skips the quit prompt. One update is kept in `pending`, so a menu check reuses a finished launch download. When there's no usable manifest (an older release, or no build for this architecture; `isMissingManifest`), it falls back to the release-page modal. Any other updater error is named in that modal on a manual check. `scripts/release.sh` signs the update tarball with `~/.tauri/glance.key`, binds the signature to the release version (`--app-version`), and writes `latest.json`. The app sets `requireSignedVersion`, so it rejects an update whose signature carries no version or a different one. The public key is `plugins.updater.pubkey` in `tauri.conf.json`.
- `theme.ts` — theme registry + preference handling. Themes are defined in `styles.css` as `:root[data-theme="…"]` blocks — each a palette + `--code-*` syntax colors + (where it diverges from the editorial default) its own `--font-*` set. Paper/Ink use Fraunces/Newsreader; Solarized uses IBM Plex, Nord uses Inter, High Contrast uses Atkinson Hyperlegible, Mesa Pop (the Escapement Labs brand) uses Bricolage Grotesque/DM Sans/DM Mono (bundled woff2 subsets in `src/assets/fonts/`). This module (pure helpers + a DOM `applyTheme`) chooses the active one via `data-theme` on `<html>`. Preference (`localStorage["glance.theme"]`) is `"auto"` (follow OS → Paper/Ink, with a live `matchMedia` listener) or a theme id. Picker UI is `showThemePicker` in `modal.ts`, opened from the native **View → Theme…** menu (`show-theme` event). An inline bootstrap in `index.html` sets `data-theme` before first paint to avoid a flash.
- `reading-width.ts` — reading-width presets (Narrow 40rem / Standard 47rem / Wide 62rem / Full width). `applyWidth` sets `--reading-w` on `<html>`, the max-width of `.rendered`. Preference is `localStorage["glance.readingWidth"]`; picker is `showReadingWidthPicker` in `modal.ts`, opened from **View → Reading Width…** (`show-reading-width` event). The `index.html` bootstrap sets the variable before first paint, so its preset table must match `WIDTHS`.
- `annotations.ts` — `Annotation`/`Resolution` types and pure list reducers (`addAnnotation`, `resolveAnnotation`, `removeAnnotation`).
- `build-anchor.ts` / `anchor-capture.ts` — capture the user's text selection (quote + prefix/suffix context + source-line hint) for storage. Anchor _resolution_ (quote → current line numbers) always happens in Rust; TS only captures and renders.
- `annotation-ui.ts` — renders the annotation rail: a collapsible header with the open count, open / orphaned / resolved sections with numbered markers and line badges, per-card actions (resolve, reopen, edit, delete), and reply threads with an inline reply box. Also applies in-view highlights to annotated source lines and mounts the floating "Comment" button that appears on text selection.

### Backend (`src-tauri/src/`)

- `lib.rs` — `run()`: registers the `tauri-plugin-single-instance` handler, builds the native macOS menu (incl. "Set up AI Integration…" / "Remove AI Integration…"), and seeds first-launch CLI args. At launch it runs `setup::refresh_integration_at_launch` on a background thread: on the first launch of a new version (`~/.glance/integration-version` differs), when Claude Code's Glance skill manifest exists, it re-installs the `mdview` wrapper and re-runs `setup_adapter` for Claude Code only. Failures go to stderr; no modal.
- `commands.rs` — `read_file` / `write_file`, plus `copy_doc_to_clipboard(path, kind)` for the tab menu: it builds the name / path / folder / markdown link in Rust from a path that must be in `OpenDocs` (so injected script can't plant arbitrary clipboard text) and pipes it to `pbcopy` with `LC_ALL=en_US.UTF-8`. `src/fixtures/markdown-links.json` is the shared contract: Rust asserts it builds those links, vitest asserts they render and resolve.
- `watcher.rs` — `notify`-based per-path file watching; emits `file-changed` (Modify/Create) and `file-removed` (Remove).
- `cli.rs` — `md_paths_from_argv` (drops flags), `to_abs`/`normalize` (resolve relative paths against cwd). Pure, with the Rust tests.
- `cli_install.rs` — writes the `~/.local/bin/mdview` wrapper.
- `anchor.rs` — pure fuzzy anchor resolution. Given a stored `Annotation` (quote + prefix/suffix context + line hint), `resolve_anchor` tries in order: exact prefix+quote+suffix match → unique or nearest quote → line-hint fallback → orphan. Returns a `Resolution` (`startLine`/`endLine` or `None` when orphaned). Shared by the GUI (via IPC) and `glance-mcp`; no I/O.
- `annotations.rs` — on-disk annotation store at `~/.glance/annotations/<sha1(absPath)>.json`. Provides `read_store`/`write_store`/`mutate_store` (cross-process lock) plus the Tauri IPC commands `read_annotations`, `add_annotation`, `remove_annotation`, `update_annotation`, `add_reply`, `resolve_anchors`, and `ensure_annotation_store`.
- `setup.rs` — the one-click "Set up AI Integration…" action, built on a `ClientAdapter` trait so integration generalizes across coding clients. Each adapter (`ClaudeAdapter`, `CursorAdapter`, …) computes a *plan* (`mcp`/`guidance`/`skill`/`open_hook` → `Plan::Write`/`AlreadyDone`/`NotSupported`) by reading — never writing — existing config; the `run_step` driver is the one place that commits writes (atomic, through symlinks, mode-preserving, refuse-to-clobber). Adapters reuse the pure merge helpers (`merge_mcp_config`, `merge_settings_hook`, `append_guidance`, `hook_script`, `skill_doc`). `setup_all_present` installs the shared `mdview` CLI once, then runs every client detected via `is_present` (defaulting to Claude Code on a fresh machine). For Claude that means: merge `glance-mcp` into `~/.claude.json`, append review guidance to `~/.claude/CLAUDE.md`, write the `glance` skill to `~/.claude/skills/glance/SKILL.md`, install `open-md-hook.sh` + a `PostToolUse`/`Write` entry in `~/.claude/settings.json`, and (Claude only, added by `with_claude_guard` after the shared plan) `guard-hook.sh` + a `PreToolUse`/`Write|Edit` entry that runs `glance-mcp --guard` to refuse edits to a doc with an `unsaved/` marker. `with_claude_guard` also adds `wait-hook.sh` + a `Stop` entry with `asyncRewake: true` and `timeout: 1770` (via `merge_settings_hook_with`, which corrects those fields in place on re-run) that `exec`s `glance-mcp --wait`. Codex CLI (`CodexAdapter`) supports all four too, in `~/.codex/`: `[mcp_servers.glance]` in `config.toml` via the `toml_edit`-based `merge_mcp_toml`/`remove_mcp_toml`/`mcp_toml_has`, guidance in `AGENTS.md`, the skill under `skills/glance/`, and hooks in `hooks.json` (same JSON layout as Claude's settings hooks; matcher `apply_patch` because Codex reports edits as `apply_patch`, and `hook_script` parses `*** Add File:` lines from `tool_input.command`; both adapters share `hooks_install_plan`/`hooks_uninstall_contents`, and all three share `guidance_plan`/`guidance_uninstall_plan`/`skill_uninstall_plan`; `install_note` appends Codex's hook-trust reminder to the result row). Cursor gets MCP (`~/.cursor/mcp.json`) + a rules doc; skill/hook fall through to the trait's `NotSupported` defaults. Each capability has a mirror uninstall (`*_uninstall` → `Plan::Delete` or a key-removing `Plan::Write`, via the pure `remove_mcp_config`/`remove_settings_hook`/`strip_guidance` helpers); `remove_all_present` reverses every detected client's connectors but deliberately leaves the shared `mdview` CLI. The Glance app menu exposes both as **Set up AI Integration…** (`setup_integration`) and **Remove AI Integration…** (`remove_integration`), both emitting the same `setup-result` event the frontend already renders. The Claude config format is unchanged from earlier versions, so existing installs need no migration — re-running setup is idempotent.
- `bin/glance-mcp.rs` — standalone stdio MCP server (second `[[bin]]` target, bundled inside `Glance.app`). Spawned by Claude Code as a subprocess. Tools: `list_annotations`, `get_annotation` (adds `context.before` / `context.after`, three lines each), `resolve_annotation` (optional `note`, appended as a Claude reply), `reply_annotation`; resource template `glance://annotations/{path}`. Re-anchors every annotation against the current file bytes on each read (`view_of` calls `resolve_anchor`). `--wait` is the `Stop` hook's waiter: it records `<token> <pid>` in `~/.glance/waiters/<session>`, polls the session's events past its cursor every 500 ms, and exits 2 with one wake line per doc (stderr) two seconds after the first new event; it exits 0 on a newer token, the toggle off, no owned doc, its parent gone, or 1,740 s. `--pending` marks the session `busy`, which stops the waiter, and prints undelivered events first. `wake.rs` holds the waiter file, cursor, `settings.json` toggle (**Glance ▸ Wake Claude on save and comment**) and `wake_status`, which the frontend asks after a save, comment or reply to show "Claude isn't listening" on the doc.

### Key flows

- **Open a file.** Two paths into the same `open-file` handling:
  - *First launch:* `lib.rs` stores resolved args in `LaunchArgs`; the frontend drains them once via `take_launch_args` in `start()`.
  - *Subsequent `mdview` calls:* the single-instance plugin receives `argv`/`cwd`, resolves paths, and `emit`s `open-file` to the already-running window.
- **Auto-reload.** Opening a doc calls `watch_file`. On `file-changed`, the frontend first checks `editorContent === contents` to swallow the **echo from our own save**, then clean tabs reload silently and dirty tabs prompt Keep-mine/Load-disk.
- **mdview wrapper** launches the binary inside the installed `Glance.app` **detached** (`… "$@" &`) — without backgrounding, the first invocation of a session would *become* the GUI process and block the terminal. It targets `current_exe()`, so it survives app updates and doesn't depend on this checkout.

## Conventions

- **Click-to-edit.** The rendered view is the only everyday view: clicking a unit (paragraph, heading, list item's own text, table row, quote paragraph, code block body, diagram, frontmatter) mounts `mountBlockEditor` inside that element, keyed by its `data-sourceline` stamps (frontmatter uses `data-frontmatter-lines`). Every keystroke is spliced into `editorContent`; `renderContent` keeps the editor across renders while the doc still holds its text at that range, and the next render after it closes (Esc, a click elsewhere, an arrow past the first/last line) redraws formatted. Commenting coexists: a drag or double/triple-click selects (a double-click on a just-opened, untouched unit closes it and selects the word), and a selection made while a unit is open survives the redraw. Mouse handling is `handleEditMouseDown`/`handleEditClick` on `document`.
- ⌘E (whole-file source view, the escape hatch for multi-block edits) is an in-window keydown listener in `app.ts`; the titlebar shows a "Source" button only while it's on. The native **File** menu (`lib.rs`) owns New… (⌘N), Open… (⌘O), Save (⌘S), and Close Tab (⌘W): each menu item emits an event that `app.ts` handles via `ipc.ts` listeners. New…/Open… pop a native dialog (`tauri-plugin-dialog`) in the Rust menu handler and both reuse the existing `open-file` flow (New… creates the empty file first); Save emits `menu-save`, Close Tab emits `close-active-tab`. Save is explicit — there is no autosave. Show in Finder (⌥⌘R) emits `show-in-finder`; the frontend answers with the active doc's path via `revealInFinder` (the opener plugin's `revealItemInDir`), since Rust doesn't know which tab is active. It's the one menu item with a *dynamic* enabled state: `lib.rs` keeps the `MenuItem` handle in `ShowInFinderItem` state, and `render()` pushes `canRevealActive(state)` (a doc is focused and still on disk) through `set_show_in_finder_enabled` whenever that answer flips.
- Keep IPC wrappers in `ipc.ts` and logic modules pure so they stay unit-testable; the reducer style (new state, no mutation) is load-bearing for the full-rerender model.
